# Tuesday

**Tuesday** helps advancement teams decide where to spend limited time: who to contact this week, what to do, and why.

Built for the GiveCampus Challenge (HackMIT).

## Quick start

```bash
npm install
npm run ingest    # extracts zip → data/raw, builds data/processed/tuesday-data.json
npm run dev       # http://localhost:3000
```

Place the hackathon dataset zip at repo root (`data-20260919T163645Z-1-001.zip`) or put CSVs in `data/raw/`.

## Architecture

| Layer | Path | Role |
|-------|------|------|
| Engine | `packages/core` | Labels, scores, action selection, queue optimizer, segments (pure TS) |
| Autopilot | `packages/m365` | Microsoft 365 OAuth, Microsoft Graph provider, tasks, approval, audit |
| Web | `apps/web` | Next.js UI + API routes |
| Data | `data/processed/tuesday-data.json` | Precomputed constituent profiles (generated by ingest) |

### Vertical slices (each kept demoable)

1. **Slice A — Weekly plan (hero):** ingest → profiles → `buildTuesday` → `/` + export CSV. Demo works even if other pages are stubbed.
2. **Slice B — Transparency:** constituent detail, timeline chart, score breakdown, evidence on queue cards.
3. **Slice C — Segments:** NL template queries + table (`ENABLE_SEGMENTS=false` disables without touching weekly plan).
4. **Slice D — Quality:** unit tests, README demo script, overview stats.

The weekly queue is never blocked by secondary work; segments and overview are additive.

## Demo script (~5 min) — judge flow

1. **Strategies** — compare *Protect donor retention* vs *Maximize immediate dollars* (8h); read pairwise insight and frontier chart.
2. Select a strategy → open portfolio → **Export strategy CSV**.
3. **Weekly plan** — *Protect renewals* → **Build my Tuesday**; show stewardship vs ask mix.
4. **Communities** — pick a class/activity cluster → **Potential connectors** → **Generate campaign plan** → export CSV.
5. Open a constituent — **Explanation** panel + **relationship journey**; show “why not upgrade” / stewardship guidance.
6. Mark **Wrong action** feedback on a queue card → rebuild to show session deprioritization (browser-local).

## Configuration

| Env | Default | Meaning |
|-----|---------|---------|
| `CURRENT_FISCAL_YEAR` | `2026` | Planning year (uses `gifts.fiscal_year`) |
| `REFERENCE_DATE` | `2026-09-01` | “Today” for recency calculations |
| `ENABLE_SEGMENTS` | `true` | Set `false` to disable segment API (weekly plan still works) |

## Key assumptions

- Only **`paid`** gifts count toward donor status and estimates.
- LYBUNT/SYBUNT use fiscal years from the dataset (school FY starts **July**).
- Opportunity dollars are **planning estimates** from prior gifts, not wealth scores.
- No employment promotions unless present in `career_history.recorded_at`.
- Contact rules: email requires `email_status=deliverable`; phone requires `phone_status=available`.

## Tuesday Autopilot (Microsoft 365)

Automation layer in `packages/m365` + `/autopilot`. The **weekly fundraising plan** works without Microsoft 365; **Autopilot actions** (email, calendar, tasks) require a real Microsoft Graph connection.

### Environment variables

Copy `.env.example` to **`.env.local` at the repo root** or **`apps/web/.env.local`**, then restart `npm run dev`:

| Variable | Purpose |
|----------|---------|
| `MICROSOFT_CLIENT_ID` | Entra app (client) ID |
| `MICROSOFT_CLIENT_SECRET` | Client secret (server only) |
| `MICROSOFT_TENANT_ID` | `common` or your tenant ID |
| `MICROSOFT_REDIRECT_URI` | `http://localhost:3000/api/auth/microsoft/callback` |
| `NEXT_PUBLIC_APP_URL` | Base URL for OAuth redirects |
| `SESSION_SECRET` | Signs the HTTP-only session cookie (min 16 chars; required in production) |

Tokens and automation data persist under `data/automation/` (gitignored). MSAL token caches are **AES-256-GCM encrypted** on disk — raw access tokens are not stored in plaintext. Account metadata (email, display name, granted scopes) is stored separately without secrets.

### Auth routes

- `GET /api/auth/microsoft/connect` — start OAuth (optional `?consent=calendar|mail|full`)
- `GET /api/auth/microsoft/callback` — authorization code exchange (server-side MSAL)
- `POST /api/auth/microsoft/disconnect` — clear session link + encrypted token cache
- `GET /api/auth/microsoft/session` — safe session JSON (never includes tokens)

This app uses **delegated permissions for the signed-in user only**. Application permissions (e.g. access to every mailbox in the tenant) are **not** required for v1.

### Microsoft Entra app registration

1. [Azure Portal](https://portal.azure.com) → **Microsoft Entra ID** → **App registrations** → **New registration**.
2. Name: `Tuesday Autopilot (dev)`. Supported account types: **Accounts in any organizational directory and personal Microsoft accounts** (matches `tenant=common`).
3. Redirect URI: **Web** → `http://localhost:3000/api/auth/microsoft/callback`.
4. **Certificates & secrets** → new client secret → copy into `MICROSOFT_CLIENT_SECRET`.
5. **API permissions** → **Microsoft Graph** → **Delegated**:
   - `openid`, `profile`, `email`, `offline_access`
   - `User.Read`
   - `Calendars.Read`, `Calendars.ReadWrite`
   - `Mail.Read`, `Mail.ReadWrite`, `Mail.Send`
6. Grant admin consent if your tenant requires it.

### Connecting Microsoft 365

1. Copy `.env.example` → `apps/web/.env.local` and fill Entra credentials + `SESSION_SECRET`.
2. Open `/autopilot` → **Connect Microsoft 365** → sign in and grant delegated permissions.
3. When disconnected, API routes return structured errors (`MICROSOFT365_NOT_CONNECTED`, `MICROSOFT365_CONFIGURATION_ERROR`, `MICROSOFT365_PERMISSION_ERROR`) with a `connectUrl`.

### Approval workflow

- Creating drafts is allowed when connected (with appropriate scopes).
- **Sending email** and **calendar invitations** always require explicit approval in the Autopilot inbox.
- Audit log records drafted, approved, rejected, and executed Graph actions (metadata only — not full mailbox bodies).

### Troubleshooting Graph permissions

- **Calendar actions fail** → use **Request calendar access** (`/api/auth/microsoft/connect?consent=calendar`).
- **Mail actions fail** → use **Request mail access** (`?consent=mail`).
- **Admin consent required** → tenant admin must grant delegated permissions in Entra.
- **Reauthenticate** → Disconnect, then Connect again.

### Autopilot demo script (~5 min)

1. **Build my Tuesday** on `/` — note a high-priority follow-up.
2. **Connect Microsoft 365** on `/autopilot`.
3. On the queue card → **Draft follow-up email** → open **Autopilot** → approve or reject in the inbox.
4. **Find meeting times** (Graph calendar) → click a slot → **Create event draft** → review in Autopilot.
5. **Activity log** shows drafted / approved / rejected / executed via Microsoft Graph.
6. Create **Weekly top-5 template** task → **Run now** → new email drafts appear for approval.

## Known limitations

- **Autopilot:** Recurring cron tasks are stored but not background-polled; use **Run now**. Graph change webhooks are interface-only. No bulk email in MVP.
- Greedy action portfolio optimizer (deterministic tie-break), not integer programming.
- Communities are seeded by shared attributes (not full pairwise graph at 20k scale).
- Feedback is browser-local only — structure is demo-ready for future learning, not a trained model.
- NL segments use intent templates, not an LLM.
- Planning opportunity ≠ causal incremental revenue (no outreach experiments in dataset).
- Re-run `npm run ingest` after pull to refresh `anonymous` flags on gifts.
